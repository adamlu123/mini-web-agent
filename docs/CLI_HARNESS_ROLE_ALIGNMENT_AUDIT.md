# Binder/Critic and Actor Role Alignment Audit

## Scope

Twenty-four parallel GPT-5.6 Luna audits read exact Binder drafts, Critic
patches, final bindings, Actor command traces, verification artifacts, scored
files, and evaluator predicates.

Every individual report is preserved under:

`docs/audits/role-alignment-v1/`

This synthesis separates:

- Binder/Critic alignment already banked;
- remaining task-visible contract gaps;
- hidden/evaluator-conflicting requirements;
- Actor native-state completion;
- canonical-surface failures;
- productive versus failed strategy persistence;
- bounded repair behavior.

## Binder/Critic: where alignment banked score

Binder/Critic produced repeatable gains when it converted visible evidence into
exact constraints:

- source identities and hashes;
- exact file/item sets;
- ordered mappings;
- constraint-feasible assignments;
- dynamic state inventories;
- exact literal values and formulas;
- canonical paths/profiles;
- preservation and no-extra requirements.

Representative gains:

- `012`: correct Q4/Q5 paper sources;
- `015`: corrected measurements and derived values;
- `019`: corrected episode/source mapping;
- `027`: corrected date serialization;
- `028`: corrected four-vaccine inventory;
- `032`: correct Tapestry theme/names/crops;
- `038`: complete lead/conversion state;
- `070`: exact incident volumes/credential/billing facts;
- `073`: exact conflict-free reviewer edges.

The historical gain audit conservatively associates approximately `+6.1` gross
points in the first 64-task jump with clear exact-contract corrections.

## Evaluator preferences Binder captures well

Evaluator-blind Binder/Critic is strongest on task-visible preferences:

1. exact canonical path, filename, account, profile, or service;
2. native editable/parser-visible state;
3. exact finite membership/cardinality and no extras;
4. exact strings, casing, punctuation, numbers, dates, and formulas when
   visibly specified;
5. source/baseline preservation;
6. ordered persistent handoffs;
7. save/reload/readback of the final surface;
8. hard prerequisites and negative constraints.

These are also the recurring properties of full-score controls.

## Remaining task-visible Binder/Critic gaps

### Exact facts weakened into prose

Task-provided exact values were sometimes weakened to:

- “valid date”;
- “positive amount”;
- “contains”;
- qualitative membership;
- semantic equivalence.

Examples: `007,034`.

### Unresolved facts promoted into exact claims

Critic identified uncertainty, but adjudication or Actor proceeded with one
plausible answer:

- timing in `042`;
- finite photo set in `046`;
- role semantics in `080`;
- numeric coordinate in `099`.

### Native serialized location omitted

Bindings named the concept but not where it must live:

- MLT playlist entry versus producer timing;
- native track/audio properties;
- connector endpoints/relationships;
- chart caches/ranges;
- XCF layer extents;
- service state versus SQLite.

### Repeated outputs compressed too aggressively

Global “all ten/all slides/all attachments” clauses sometimes lacked per-item
identity/content/readback:

- `083,087,090,096,102`.

Representative proof is suitable only for shared invariants such as file type;
item content and mappings need one-to-one coverage.

### Canonical surface identity unresolved

Actor and evaluator could use different:

- browser sessions;
- Zotero profiles/databases;
- project services;
- filesystem roots;
- archive copies.

Examples: `020,033,036,062,081,098`.

## What Binder/Critic cannot safely align

Runtime Binder must not infer:

- hidden seat IDs;
- magic temp files;
- hidden certificates;
- hard-coded alternate databases;
- arbitrary case-sensitive key names;
- hidden reference pixels/audio;
- undocumented geometry thresholds;
- evaluator-only representation choices.

Examples: `021,023,024,035,037,044,051,060,061,089`.

These remain unknown/conflict findings. A task-faithful binding may still score
poorly under a contradictory evaluator.

## Actor: recurring successful execution sequence

Successful Actors repeatedly:

1. inspect initialized state and source identity;
2. choose the canonical evaluator-facing surface;
3. stage uncertain acquisition outside the deliverable;
4. create a real persistent artifact/state early;
5. apply a scoped mutation or coherent mutation batch;
6. validate at stage boundaries;
7. save/reload/reopen;
8. read back native fields, hashes, geometry, relationships, or service state;
9. remove stale alternatives;
10. submit only after the readback agrees.

Examples:

- `001`: one scoped ICS rewrite plus parsed event checks;
- `006`: staged PDF acquisition plus exact final inventory;
- `012`: source identity plus byte/hash verification;
- `022`: real app upload/state/reload;
- `028`: native booking state;
- `066`: narrow OOXML mutation and rerender;
- `091`: repeated native parser/render geometry closure;
- `107`: native KiCad API, connectivity, and archive validation.

## Why Actor fails

### Missing or late canonical artifact

- game ending/save never created: `047,048`;
- canonical GGB absent until a later different trajectory: `059`;
- source research consumed the run before deliverables: `011`.

### Wrong canonical surface

- transient React/UI state differed from cart: `020`;
- wrong filesystem/profile/database: `033,036,062`;
- SQLite differed from live service: `081`;
- visible confirmation differed from authenticated API state: `098`.

### Wrong native representation

- arbitrary connector geometry: `049`;
- padded proxy layers: `051`;
- wrong MLT fields/services: `042,055`;
- structurally plausible but visually/native-incomplete slides: `087,090`;
- guessed CAD dimensions/surfaces: `103`;
- incomplete PCB placement/routing/archive: `108`.

### Domain-quality limitation

- masking/matting: `053,054`;
- reference video geometry: `055,056`;
- gameplay: `047,048`;
- transcription: `067`;
- expert segmentation/CAD.

### Strategy persistence after falsification

Failed routes remained active after:

- repeated click/drag failure;
- source 403;
- visible mask defect;
- missing file;
- read-only filesystem;
- failed macro functionality.

Compaction often preserved the current failed premise. Successful persistence
instead preserved a tested invariant and a next state-changing action.

## Productive strategy persistence

Persistence is productive when each loop:

- falsifies one assumption;
- mutates evaluator-facing state;
- or reads back one bounded alternative.

Examples:

- `039`: complete dynamic-state inventory followed by idempotent mutations;
- `095`: missing-source detection → legitimate recovery → native artifact;
- `091`: parser/render finding → geometry correction → rerender.

Persistence becomes thrash when calls only gather more metadata or repeat the
same action family without changing state.

## Repair

Original context helps for local deterministic defects on an existing artifact:

- form fields (`098`);
- CAD features (`104`);
- selected native geometry (`103`);
- limited routing (`108`).

It fails or harms when:

- semantic strategy is wrong (`009,019`);
- whole project is rebuilt (`050`);
- visual approximation remains wrong (`053`);
- artifact/surface is missing;
- infrastructure is broken.

Bounded repair requires exact defect scope, snapshot/preservation, one limited
continuation, native readback, and rollback. Ambiguous facts remain unresolved.

## Broader below-0.5 frontier

The persistent frontier is not mainly nonexistent artifacts.

Most tasks have persistent state, but it is:

- incomplete;
- on the wrong surface;
- encoded in the wrong native representation;
- semantically/domain-defective;
- or task-faithful but evaluator-conflicting.

Non-exclusive frontier projection:

- evaluator/task conflict: 11;
- domain/reference limited: 10;
- infrastructure: 5;
- narrow native invariant: 6;
- clean broad-planning failure: 1.

## Generalizable principles

### Binder/Critic

1. Exact visible facts require exact constraints.
2. Unique support is required for exact claims.
3. Unresolved facts stay unresolved and can block dependent action.
4. Finite sets are enumerated one-to-one.
5. Bind native serialized location/relationships, not only semantic intent.
6. Resolve canonical app/profile/path/service identity before Actor mutation.
7. Separate native and rendered predicates.
8. Preserve evaluator conflicts rather than guessing.

### Actor

1. Select the canonical surface before writing.
2. Stage uncertain inputs outside the deliverable.
3. Create a real persistent result early.
4. Use short feedback loops for uncertain GUI/visual/geometry work.
5. Batch deterministic operations with assertions.
6. Save/reload/read back the same surface.
7. Retire falsified strategies.
8. Never substitute synthetic/proxy state where provenance/native semantics
   matter.
9. Treat compaction as a state-and-next-action handoff, not narrative memory.
10. Submit only after native and rendered state agree where both matter.

## What this audit does not establish

The principles above describe the successful/failing traces. They do not by
themselves qualify a new harness implementation.

Any implementation proposal remains subject to
`docs/CLI_HARNESS_RESEARCH_GATES.md`.
